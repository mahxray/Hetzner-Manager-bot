# Hetzner Manager Bot

ربات فارسی و شخصی تلگرام برای مدیریت چند پروژهٔ **Hetzner Cloud**؛ هر پروژه با نام و API Token مستقل، قابل نصب روی VPS با Docker Compose.

> این پروژه رابط API عمومی Cloud است. معادل تمام وب‌سایت حساب هتزنر نیست: مدیریت حساب، پرداخت و فاکتور، ساخت پروژه و API Token، سرویس Robot، Storage Box و Object Storage در این نسخه پیاده‌سازی نشده‌اند. ورود با نام کاربری و رمز حساب هتزنر لازم نیست.

## امکانات

- افزودن چند پروژه، انتخاب مستقل هر پروژه و حذف اتصال آن از بات؛ داده‌های هر کاربر فقط برای خودش قابل دسترسی است.
- منوی سریع سرورها با صفحه‌بندی: وضعیت و IPv4، روشن کردن، خاموش کردن نرم، قطع برق، ری‌استارت، اسنپ‌شات و حذف.
- فهرست **۱۹۰ عملیات** از نسخهٔ ذخیره‌شدهٔ مشخصات رسمی Cloud API: سرورها، ایمیج‌ها و بکاپ‌ها، شبکه‌ها، فایروال‌ها، دیسک‌ها، IPها، SSH Keys، Load Balancers، گواهی‌ها، Placement Groups، قیمت‌ها و DNS Zones/RRSets.
- عملیات پیشرفته از طریق منوی گروه‌ها، با **ورودی JSON**، نمونهٔ قابل ویرایش و فایل JSON Schema برای راهنمای فیلدها؛ این بخش فرم گرافیکی یا مراحل فارسی اختصاصی برای هر عملیات ندارد. عنوان عملیات پیشرفته مطابق مستندات رسمی انگلیسی است.
- ارسال ورودی به صورت متن یا فایل JSON تا ۵۱۲ کیلوبایت؛ دریافت پاسخ بزرگ به صورت فایل.
- تأیید تمام درخواست‌های تغییردهنده، با نمایش پروژه و شناسهٔ منبع؛ تأیید یک‌بارمصرف و دارای مهلت ۲ دقیقه. جابه‌جایی پروژه یا `/cancel` تأیید قبلی را لغو می‌کند.
- پیگیری Actionهای هتزنر با دکمه؛ پذیرش درخواست به معنی پایان کار نیست.
- توکن‌های رمزگذاری‌شده با Fernet در SQLite؛ فقط شناسه‌های مجاز تلگرام و فقط چت خصوصی.
- مخفی کردن اطلاعات محرمانهٔ پاسخ؛ دریافت پاسخ کامل مثل گذرواژهٔ سرور یا مشخصات کنسول با درخواست جداگانه و یک‌بارمصرف در همان چت، تا ۲ دقیقه.

پوشش فهرست API به معنی تست زندهٔ تمام عملیات نیست. قابلیت هر درخواست به سطح دسترسی توکن، وضعیت منبع، محدودیت حساب و موجودی هتزنر وابسته است. صفحات فهرست پیشرفته با `query.page` و `query.per_page` خوانده می‌شوند؛ بات همهٔ صفحات را خودکار جمع نمی‌کند. کنسول، اطلاعات اتصال API را برمی‌گرداند؛ ترمینال تعاملی داخل تلگرام ندارد.

## نصب عمومی روی VPS

پیش‌نیاز: Linux و Git، همراه دسترسی root یا sudo. اسکریپت روی Ubuntu 22.04/24.04/26.04/26.10 و Debian 12/13، Docker Engine، افزونهٔ Compose و Python 3 را در صورت نیاز نصب می‌کند. دسترسی خروجی HTTPS به مخازن بسته‌ها، Telegram و Hetzner لازم است. پورت ورودی، دامنه و SSL لازم نیست؛ بات از long polling استفاده می‌کند.

```bash
git clone https://github.com/mahxray/Hetzner-Manager-bot.git
cd Hetzner-Manager-bot
bash install.sh
```

نصب Docker از مخزن APT رسمی و مطابق [راهنمای Ubuntu](https://docs.docker.com/engine/install/ubuntu/) و [راهنمای Debian](https://docs.docker.com/engine/install/debian/) انجام می‌شود. اگر Docker و Compose از قبل آماده باشند، دوباره نصب نمی‌شوند. در صورت نیاز سرویس Docker راه‌اندازی و برای اجرای دستورات همین اسکریپت از sudo استفاده می‌شود؛ عضویت گروه کاربر تغییر نمی‌کند. اگر بسته‌های موجود با نصب رسمی تعارض داشته باشند، نصب متوقف می‌شود و آن بسته‌ها خودکار حذف نمی‌شوند. روی سایر توزیع‌ها Docker و Compose را دستی نصب کنید؛ اگر از قبل آماده باشند، اسکریپت می‌تواند بات را اجرا کند.

در اجرای اول، اسکریپت این موارد را می‌پرسد:

1. توکن بات ساخته‌شده توسط [BotFather](https://t.me/BotFather)؛ ورودی نمایش داده نمی‌شود.
2. شناسهٔ عددی تلگرام خودتان. برای چند مدیر، شناسه‌ها را با ویرگول جدا کنید. نام کاربری و شماره تلفن پذیرفته نیست.

کلید رمزگذاری به‌صورت تصادفی ساخته و همراه تنظیمات در `.env` ذخیره می‌شود. **این فایل را محرمانه نگه دارید و از آن نسخهٔ پشتیبان بگیرید.** اسکریپت فایل موجود و کلید قبلی را جایگزین نمی‌کند. از روی `.env.example` هم می‌توانید تنظیمات را دستی بسازید؛ مقدار نمونهٔ `ENCRYPTION_KEY` معتبر نیست.

سپس در تلگرام `/start` بفرستید، «افزودن پروژه» را بزنید، نام پروژه و توکن همان پروژه را وارد کنید. برای پروژهٔ بعدی همین کار را تکرار کنید. توکن در Console هتزنر، داخل هر پروژه، بخش Security → API Tokens ساخته می‌شود. توکن Read برای مشاهده و توکن Read & Write برای تغییر منابع لازم است. توکن Read نمی‌تواند عملیات تغییردهنده را انجام دهد و خطای هتزنر نمایش داده می‌شود.

همهٔ مدیران مجاز دسترسی یکسان به پروژه‌های یکدیگر ندارند: هر مدیر باید پروژه‌های خودش را ثبت کند. شناسهٔ مالک در دیتابیس و همهٔ عملیات بررسی می‌شود. بات برای ثبت‌نام عمومی کاربران باز نیست؛ عمومی بودن این مخزن یعنی هر کس می‌تواند نسخهٔ خودش را نصب کند.

### وارد کردن توکن بدون فرستادن آن در تلگرام

چت بات تلگرام رمزگذاری سرتاسری ندارد. برای ورود توکن از داخل VPS:

```bash
docker compose exec bot python -m bot.manage add-project --owner 123456789 --name production
```

توکن به‌صورت مخفی پرسیده می‌شود و قبل از ذخیره با API بررسی می‌شود. مالک باید در `ALLOWED_USER_IDS` باشد. بعد در تلگرام `/projects` را بزنید. برای چند پروژه از نام‌های متفاوت استفاده کنید.

## نمونهٔ استفادهٔ پیشرفته

در پروژه، «تمام عملیات Cloud» → گروه مربوطه → عملیات را انتخاب کنید. نمونه را **با مقادیر پروژهٔ خودتان** عوض کنید؛ شناسه‌ها و نام‌های نمونه واقعی نیستند. فیلدهای اختیاری را از «راهنمای فیلدها» یا [مستندات API](https://docs.hetzner.cloud/reference/cloud) ببینید. فایل Schema راهنماست؛ خود آن را به‌عنوان ورودی اجرا ارسال نکنید.

ساخت سرور، با کلید SSH از قبل ثبت‌شده در همان پروژه:

```json
{
  "body": {
    "name": "my-server",
    "server_type": "cpx22",
    "image": "ubuntu-24.04",
    "location": "nbg1",
    "ssh_keys": [123456]
  }
}
```

نوع سرور، موقعیت و ایمیج را از عملیات فهرست همان گروه‌ها انتخاب کنید؛ دسترس‌پذیری و قیمتشان ممکن است تغییر کند. ساخت منابع هزینه دارد و قبل از اجرا تأیید می‌خواهد.

صفحهٔ دوم فهرست سرورها:

```json
{"query": {"page": 2, "per_page": 10}}
```

تغییر نام سرور با عملیات Update a Server:

```json
{"path": {"id": 123456}, "body": {"name": "new-name"}}
```

فعال کردن Rescue با عملیات مربوط در Server Actions:

```json
{"path": {"id": 123456}, "body": {"type": "linux64", "ssh_keys": [123456]}}
```

برای ادامهٔ عملیات طولانی، دکمهٔ «پیگیری عملیات» را بزنید تا وضعیت `success` یا `error` دریافت شود. در timeout بات درخواست تغییردهنده را خودکار تکرار نمی‌کند؛ قبل از اجرای مجدد، وضعیت سرور یا منبع را بررسی کنید. تکرار درخواست ساخت ممکن است منبع و هزینهٔ اضافه ایجاد کند.

## مدیریت سرویس

```bash
docker compose ps
docker compose logs --tail=50 bot
docker compose restart bot
docker compose stop bot
docker compose start bot
```

به‌روزرسانی:

```bash
git pull --ff-only
docker compose up -d --build
```

تنها یک نمونهٔ polling با یک توکن تلگرام اجرا کنید. اگر متغیرهای `.env` را تغییر دادید، برای اعمال آن `docker compose up -d --force-recreate` اجرا کنید. داده‌ها در volume پایدار `bot-data` می‌مانند؛ `docker compose down -v` آن‌ها را حذف می‌کند.

### پشتیبان‌گیری

برای کپی سازگار دیتابیس، ابتدا بات را متوقف کنید:

```bash
docker compose stop bot
mkdir -p backups
chmod 700 backups
docker compose cp bot:/app/data/projects.db backups/projects.db
cp .env backups/.env
chmod 600 backups/projects.db backups/.env
docker compose start bot
```

پوشهٔ backups را در محل امن دیگری نگه دارید؛ دیتابیس و کلید کنار هم امکان خواندن توکن‌ها را می‌دهند. برای بازیابی، `.env` اصلی را برگردانید، کانتینر را با `docker compose create` بسازید، دیتابیس را به `/app/data/projects.db` کپی کنید و مالک آن را به `10001:10001` تغییر دهید، سپس سرویس را شروع کنید. کلید جدید با دیتابیس قبلی قابل استفاده نیست.

## اجرای بدون Docker / توسعه

Python 3.13 یا 3.14:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/setup.py
python -m bot.main
```

در Windows از `.venv\Scripts\Activate.ps1` استفاده کنید. برای سرویس دائمی، روش Docker بالاتر دارای سیاست restart است؛ اجرای مستقیم در ترمینال فقط تا زمان باز بودن پردازش ادامه دارد.

تست‌ها بدون توکن واقعی و با HTTP شبیه‌سازی‌شده اجرا می‌شوند:

```bash
python -m unittest discover -s tests -v
python -m compileall -q bot scripts
bash -n install.sh
```

CI همین تست‌ها را روی Linux و Python 3.13/3.14 اجرا می‌کند و image را می‌سازد. CI شامل تست روی حساب واقعی هتزنر یا ارسال واقعی تلگرام نیست.

## امنیت و محدودیت‌ها

- `.env`، دیتابیس، لاگ، محیط مجازی و backups داخل Git قرار نمی‌گیرند. کلید واقعی را در issue، commit یا screenshot منتشر نکنید.
- توکن‌ها در دیتابیس رمزگذاری می‌شوند؛ این کار در برابر دسترسی کامل مهاجم به VPS و `.env` محافظت ایجاد نمی‌کند.
- پیام توکن و ورودی JSON به‌صورت best effort از تلگرام حذف می‌شوند؛ در صورت شکست حذف، بات اطلاع می‌دهد. پیام پاسخ محرمانه پس از درخواست شما در چت باقی می‌ماند و باید دستی حذف شود.
- تأییدها، ورودی موقت و پاسخ محرمانه فقط در حافظه‌اند و با restart از بین می‌روند. اطلاعات منقضی‌شده حداکثر در چرخهٔ پاک‌سازی ۱۵ ثانیه‌ای حذف می‌شوند.
- حذف اتصال پروژه از بات، منابع هتزنر را حذف یا توکن هتزنر را باطل نمی‌کند. برای ابطال توکن، به Console بروید. نسخه‌های پشتیبان قبلی ممکن است همچنان توکن رمزگذاری‌شده را داشته باشند.
- محدودیت نرخ هتزنر نمایش داده می‌شود؛ درخواست تغییردهنده خودکار retry نمی‌شود.
- بات بر اساس مشخصات ذخیره‌شده ساخته می‌شود؛ در زمان اجرا کد یا Schema جدید از اینترنت بارگیری نمی‌کند.

## به‌روزرسانی فهرست API

```bash
python scripts/update_catalog.py
python -m unittest discover -s tests -v
git diff -- bot/catalog.json
```

تغییر فهرست را پیش از انتشار بررسی کنید؛ شناسهٔ عملیات، روش، مسیر و ساختار ورودی مستقیماً رفتار بات را تعیین می‌کنند. مبدأ، زمان دریافت و SHA-256 نسخهٔ اصلی در `bot/catalog.json` ثبت است. این فهرست از [مشخصات رسمی هتزنر](https://docs.hetzner.cloud/cloud.spec.json) استخراج شده؛ توضیحات و Schemaهای هتزنر متعلق به منبع اصلی‌اند. کد این پروژه با مجوز MIT منتشر می‌شود.

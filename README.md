# Hetzner Manager Bot

ربات فارسی و شخصی تلگرام برای مدیریت چند پروژهٔ **Hetzner Cloud**؛ هر پروژه با نام و API Token مستقل، قابل نصب روی VPS با Docker Compose.

> این پروژه رابط API عمومی Cloud است. معادل تمام وب‌سایت حساب هتزنر نیست: مدیریت حساب، پرداخت و فاکتور، ساخت پروژه و API Token، سرویس Robot، Storage Box و Object Storage در این نسخه پیاده‌سازی نشده‌اند. ورود با نام کاربری و رمز حساب هتزنر لازم نیست.

## امکانات

- تنظیم واحد نمایش قیمت به **یورو (EUR)** یا **ریال (IRR)** با `/currency` یا دکمهٔ «واحد قیمت»؛ انتخاب هر کاربر ذخیره می‌شود. قیمت پلن‌ها هنگام انتخاب و در صفحهٔ سرور با دو رقم اعشار نمایش داده می‌شود؛ مبالغ تبدیل‌شده با علامت `≈` و منبع و تاریخ/زمان نرخ همراه‌اند.
- مدیریت ادمین از داخل بات: مالک با شناسهٔ عددی تلگرام ادمین اضافه می‌کند و پروژه‌های دلخواه خودش را به او اختصاص می‌دهد. ادمین فقط پروژه‌های اختصاص‌یافته را می‌بیند و عملیات همان‌ها را انجام می‌دهد؛ مدیریت ادمین‌ها، افزودن توکن پروژه و حذف اتصال پروژه مخصوص مالک است.
- انتخاب زبان **فارسی / English** با دکمهٔ «زبان / Language» یا دستور `/language`؛ انتخاب هر کاربر مستقل ذخیره و پس از به‌روزرسانی و ری‌استارت حفظ می‌شود. نام پروژه، سرور و ورودی کاربر تغییر نمی‌کند؛ نام‌های فنی و مستندات اصلی API به زبان منبع باقی می‌مانند.
- صفحهٔ هر سرور بخش‌های نمودار، اسنپ‌شات و بکاپ، شبکه و IP، فایروال، دیسک، Load Balancer، Rescue، ISO، تغییر پلن، نصب مجدد و حذف را دارد. شناسهٔ سرور در عملیات مربوط خودکار وارد می‌شود؛ اتصال منبع به سرور نیز پیش از اجرا تأیید می‌گیرد.
- نمودار PNG دادهٔ CPU، شبکه و دیسک در یک ساعت گذشته، با محور زمان UTC و دریافت مستقیم از API؛ سری‌های دیسک با واحدهای متفاوت جدا رسم می‌شوند.
- جداسازی (Unassign) و تعویض Primary IPv4/IPv6 از داخل همان سرور، با انتخاب IP آزاد هم‌نوع در همان موقعیت. سرور باید خاموش و بدون قفل عملیات باشد. ساخت IP جدید از این صفحه، موقعیت همان سرور را انتخاب می‌کند و IP را برای انتخاب بعدی آزاد نگه می‌دارد.
- تعویض IP پیش از جداسازی در دیتابیس ثبت می‌شود؛ بات منتظر نتیجهٔ عملیات هتزنر می‌ماند. اگر تخصیص جدید شکست بخورد، برای برگرداندن IP قبلی تلاش می‌کند. در صورت شکست بازیابی، وضعیت نیمه‌کاره حفظ می‌شود و دکمهٔ «بازیابی IP ناتمام» در دسترس است؛ راه‌اندازی بعدی بات نیز این موارد را بررسی می‌کند. تغییر بیرونی یا سرور روشن/قفل‌شده خودکار بازنویسی نمی‌شود.
- منوی پروژه: «سرورهای من»، «ساخت سرور»، «اسنپ‌شات و بکاپ»، «آدرس‌های IP» و تنظیمات پروژه برای تغییر نام و API key.
- ساخت Floating IP مرحله‌ای است: نام، نوع، سرور و ریجن سازگار را می‌پرسد؛ بعد IP را به سرور وصل می‌کند و دستور موقت تنظیم Linux را نشان می‌دهد. حذف Floating IP ابتدا آن را از سرور جدا می‌کند.
- ساخت سرور سؤال‌به‌سؤال: نام ← کشور/شهر ← پلن موجود با قیمت همان موقعیت و واحد پول API ← سیستم‌عامل سازگار با معماری ← کلید SSH یا دریافت گذرواژه ← تأیید نهایی.
- در مسیر ساخت، فقط پلن‌هایی نمایش داده می‌شوند که API رسمی در `server_type.locations[].available` برای موقعیت انتخاب‌شده موجود اعلام کند و تاریخ پایان عرضه‌شان نرسیده باشد. موجودی نامعلوم نمایش داده نمی‌شود. قبل از تأیید و پیش از ارسال درخواست ساخت، موجودی دوباره خوانده می‌شود؛ این بررسی ظرفیت را رزرو نمی‌کند و هتزنر ممکن است در همان فاصله ظرفیت را تمام کند. قیمت نشان‌داده‌شده مربوط به پلن است؛ IP و سایر خدمات می‌توانند هزینهٔ جدا داشته باشند.
- کارت خوانای سرور: وضعیت فارسی، IP، موقعیت، CPU/RAM، دیسک، سیستم‌عامل، ترافیک خروجی و وضعیت بکاپ. روشن/خاموش و ری‌استارت در صفحهٔ سرور؛ تغییر نام، پلن، نصب مجدد، Rescue، گذرواژه و حذف در «تغییرات سرور».
- مسیر جدا برای اسنپ‌شات و بکاپ، ساخت و تغییر نام و حذف اسنپ‌شات و بازیابی روی سرور انتخابی؛ مسیر جدا برای ساخت، تخصیص، جداسازی و حذف Primary IP.
- فهرست سرورها در هر بار نمایش یا تازه‌سازی از پروژهٔ فعلی خوانده می‌شود؛ سرورهای حذف‌شده کش نمی‌شوند و موارد در حال حذف نمایش داده نمی‌شوند. سرور خاموش همچنان یک سرور موجود است و در فهرست می‌ماند.
- افزودن چند پروژه، انتخاب مستقل هر پروژه و حذف اتصال آن از بات؛ داده‌های هر کاربر فقط برای خودش قابل دسترسی است.
- منوی سریع سرورها با صفحه‌بندی: وضعیت و IPv4، روشن کردن، خاموش کردن نرم، قطع برق، ری‌استارت، اسنپ‌شات و حذف.
- منوی مدیریت منابع با فهرست صفحه‌بندی‌شده، انتخاب منبع، مشاهده و عملیات مخصوص همان منبع؛ شناسهٔ آن در فرم عملیات خودکار وارد می‌شود.
- فهرست **۱۹۰ عملیات** از نسخهٔ ذخیره‌شدهٔ مشخصات رسمی Cloud API: سرورها، ایمیج‌ها و بکاپ‌ها، شبکه‌ها، فایروال‌ها، دیسک‌ها، IPها، SSH Keys، Load Balancers، گواهی‌ها، Placement Groups، قیمت‌ها و DNS Zones/RRSets.
- فرم دکمه‌ای برای ورود مرحله‌ای فیلدهای عملیات؛ تنظیمات تودرتو، فهرست‌ها، قوانین فایروال، زیرشبکه‌ها، رکوردهای DNS و برچسب‌ها بدون نوشتن JSON قابل ویرایش‌اند. نام فیلدهای متداول فارسی و راهنمای فنی مطابق متن API انگلیسی است. فیلدهای خاص ترجمه‌نشده با نام اصلی نمایش داده می‌شوند.
- انتخاب مدل سرور، ایمیج، موقعیت، دیتاسنتر، کلید SSH، شبکه، ISO و برخی منابع دیگر از فهرست واقعی پروژه، همراه امکان ورود دستی.
- حالت پیشرفتهٔ **JSON**، نمونهٔ قابل ویرایش و فایل JSON Schema نیز کنار هر عملیات در دسترس است.
- ارسال ورودی به صورت متن یا فایل JSON تا ۵۱۲ کیلوبایت؛ دریافت پاسخ بزرگ به صورت فایل.
- تأیید تمام درخواست‌های تغییردهنده، با نمایش پروژه و شناسهٔ منبع؛ تأیید یک‌بارمصرف و دارای مهلت ۲ دقیقه. جابه‌جایی پروژه یا `/cancel` تأیید قبلی را لغو می‌کند.
- پیگیری Actionهای هتزنر با دکمه؛ پذیرش درخواست به معنی پایان کار نیست.
- توکن‌های رمزگذاری‌شده با Fernet در SQLite؛ فقط شناسه‌های مجاز تلگرام و فقط چت خصوصی.
- مخفی کردن اطلاعات محرمانهٔ پاسخ؛ دریافت پاسخ کامل مثل گذرواژهٔ سرور یا مشخصات کنسول با درخواست جداگانه و یک‌بارمصرف در همان چت، تا ۲ دقیقه.

پوشش فهرست API به معنی تست زندهٔ تمام عملیات نیست. قابلیت هر درخواست به سطح دسترسی توکن، وضعیت منبع، محدودیت حساب و موجودی هتزنر وابسته است. صفحات فهرست پیشرفته از بخش «فیلتر و صفحه‌بندی» یا `query.page` و `query.per_page` خوانده می‌شوند؛ بات همهٔ صفحات را خودکار جمع نمی‌کند. کنسول، اطلاعات اتصال API را برمی‌گرداند؛ ترمینال تعاملی داخل تلگرام ندارد. فرم ساختاریافته جای اعتبارسنجی سمت هتزنر را نمی‌گیرد؛ سازگاری معماری، مدل و موقعیت و قیمت را پیش از تأیید بررسی کنید. ورودی‌های خاص مثل مقدار صریح null یا ساختارهای آزاد پیچیده را می‌توان از حالت JSON ارسال کرد.

## نصب عمومی روی VPS

پیش‌نیاز: Linux و Git، همراه دسترسی root یا sudo. اسکریپت روی Ubuntu 22.04/24.04/26.04/26.10 و Debian 12/13، Docker Engine، افزونهٔ Compose و Python 3 را در صورت نیاز نصب می‌کند. دسترسی خروجی HTTPS به مخازن بسته‌ها، Telegram و Hetzner لازم است. پورت ورودی، دامنه و SSL لازم نیست؛ بات از long polling استفاده می‌کند.

```bash
git clone https://github.com/mahxray/Hetzner-Manager-bot.git
cd Hetzner-Manager-bot
bash install.sh
```

نصب Docker از مخزن APT رسمی و مطابق [راهنمای Ubuntu](https://docs.docker.com/engine/install/ubuntu/) و [راهنمای Debian](https://docs.docker.com/engine/install/debian/) انجام می‌شود. اگر Docker و Compose از قبل آماده باشند، دوباره نصب نمی‌شوند. در صورت نیاز سرویس Docker راه‌اندازی و برای اجرای دستورات همین اسکریپت از sudo استفاده می‌شود؛ عضویت گروه کاربر تغییر نمی‌کند. اگر بسته‌های موجود با نصب رسمی تعارض داشته باشند، نصب متوقف می‌شود و آن بسته‌ها خودکار حذف نمی‌شوند. روی سایر توزیع‌ها Docker و Compose را دستی نصب کنید؛ اگر از قبل آماده باشند، اسکریپت می‌تواند بات را اجرا کند.

در اجرای اول، اسکریپت این موارد را می‌پرسد:

1. توکن بات ساخته‌شده توسط [BotFather](https://t.me/BotFather)؛ ورودی نمایش داده نمی‌شود.
2. شناسهٔ عددی تلگرام خودتان به‌عنوان مالک. برای چند مالک مستقل، شناسه‌ها را با ویرگول جدا کنید. ادمین محدود به پروژه را بعداً از داخل بات اضافه کنید و شناسه‌اش را در `ALLOWED_USER_IDS` قرار ندهید. نام کاربری و شماره تلفن پذیرفته نیست.

کلید رمزگذاری به‌صورت تصادفی ساخته و همراه تنظیمات در `.env` ذخیره می‌شود. **این فایل را محرمانه نگه دارید و از آن نسخهٔ پشتیبان بگیرید.** اسکریپت فایل موجود و کلید قبلی را جایگزین نمی‌کند. از روی `.env.example` هم می‌توانید تنظیمات را دستی بسازید؛ مقدار نمونهٔ `ENCRYPTION_KEY` معتبر نیست.

سپس در تلگرام `/start` بفرستید، «افزودن پروژه» را بزنید، نام پروژه و توکن همان پروژه را وارد کنید. برای پروژهٔ بعدی همین کار را تکرار کنید. توکن در Console هتزنر، داخل هر پروژه، بخش Security → API Tokens ساخته می‌شود. توکن Read برای مشاهده و توکن Read & Write برای تغییر منابع لازم است. توکن Read نمی‌تواند عملیات تغییردهنده را انجام دهد و خطای هتزنر نمایش داده می‌شود.

هر مالک فقط پروژه‌های خودش و پروژه‌هایی را که صریحاً به او واگذار شده‌اند می‌بیند. ادمین‌های اضافه‌شده در بات فقط پروژه‌های اختصاص‌یافته را می‌بینند؛ نیازی به دریافت یا وارد کردن API Token ندارند. دسترسی پروژه هنگام دریافت اطلاعات، تأیید عملیات، دریافت پاسخ محرمانه و تغییر IP دوباره بررسی می‌شود. بات برای ثبت‌نام عمومی کاربران باز نیست؛ عمومی بودن این مخزن یعنی هر کس می‌تواند نسخهٔ خودش را نصب کند.

### افزودن ادمین و اختصاص پروژه

با حساب مالک `/admins` را بفرستید یا در فهرست پروژه‌ها «مدیریت ادمین‌ها» را بزنید:

1. «افزودن ادمین» را بزنید و شناسهٔ عددی تلگرام و نام دلخواه ادمین را وارد کنید.
2. پروژه‌های مجاز را با دکمه‌ها علامت بزنید؛ هر تعداد پروژه از پروژه‌های خودتان قابل انتخاب است.
3. «ذخیرهٔ دسترسی‌ها» را بزنید. ادمین سپس باید خودش بات را باز کند و `/start` بفرستد؛ بات به‌صورت خودکار پیام دعوت نمی‌فرستد.

ادمین روی منابع پروژهٔ انتخاب‌شده کنترل کامل عملیاتی دارد؛ از جمله ساخت و حذف سرور، ایجاد هزینه و دریافت گذرواژه‌های عملیاتی. توکن هتزنر در دیتابیس رمزگذاری‌شدهٔ مالک باقی می‌ماند و برای واگذاری پروژه کپی یا در رابط نمایش داده نمی‌شود. این نقش فقط‌خواندنی نیست. برای لغو دسترسی، علامت پروژه را بردارید و ذخیره کنید؛ برای حذف ادمین از دکمهٔ «حذف ادمین» استفاده کنید. لغو، دکمه‌ها و تأییدهای قدیمی را هم مسدود می‌کند؛ عملیات قبلاً ارسال‌شده به هتزنر را لغو نمی‌کند.

ادمینی که به هیچ پروژه‌ای دسترسی ندارد فقط پیام نبود پروژه و تنظیم زبان را می‌بیند. دسترسی‌ها بعد از ری‌استارت و `mhx update` باقی می‌مانند. هر مالک فقط ادمین‌ها و واگذاری‌های خودش را مدیریت می‌کند؛ حذف یک ادمین توسط یک مالک، واگذاری مستقل مالک دیگر را حذف نمی‌کند. بازیابی تغییر IP نیمه‌کاره با اختیار مالک اصلی پروژه قابل انجام است، حتی اگر دسترسی ادمین آغازکننده لغو شده باشد؛ اعلان بازیابی برای مالک اصلی فرستاده می‌شود.

حذف شناسهٔ یک مالک از `ALLOWED_USER_IDS`، پس از اعمال تنظیمات و راه‌اندازی مجدد، واگذاری‌های صادرشده توسط همان مالک را هم غیرفعال می‌کند؛ پروژه‌ها و توکن‌های ذخیره‌شده حذف نمی‌شوند. برای ادمین محدود نیازی به ویرایش `.env` یا ری‌استارت نیست.

### پشتیبان و بازیابی داده‌های بات

هر مالک می‌تواند `/backup` را برای دریافت فایل SQLite شامل پروژه‌های خودش، توکن‌های API رمزگذاری‌شده، ادمین‌ها، واگذاری پروژه‌ها و ترجیحات زبان/قیمت بزند. عملیات نیمه‌تمام IP داخل فایل پشتیبان نیست. فایل و `.env` را جداگانه و محرمانه نگه دارید؛ فایل پشتیبان به همان `ENCRYPTION_KEY` نیاز دارد و جایگزین پشتیبان از `.env` نیست. برای بازیابی، `/restore` را بزنید و فایل پشتیبان را ارسال کنید. فایل با کلید رمزگذاری فعلی اعتبارسنجی می‌شود و قبل از تأیید، هیچ داده‌ای تغییر نمی‌کند. بازیابی فقط داده‌های همان مالک را جایگزین می‌کند؛ پیش از آن یک نسخهٔ خودکار از داده‌های فعلی او به خودش ارسال می‌شود. بازیابی وقتی تغییر IP نیمه‌تمام وجود داشته باشد متوقف می‌شود. فایل باید کمتر از ۲۰ مگابایت باشد.

### وارد کردن توکن بدون فرستادن آن در تلگرام

چت بات تلگرام رمزگذاری سرتاسری ندارد. برای ورود توکن از داخل VPS:

```bash
docker compose exec bot python -m bot.manage add-project --owner 123456789 --name production
```

توکن به‌صورت مخفی پرسیده می‌شود و قبل از ذخیره با API بررسی می‌شود. مالک باید در `ALLOWED_USER_IDS` باشد. بعد در تلگرام `/projects` را بزنید. برای چند پروژه از نام‌های متفاوت استفاده کنید.

## کارهای روزمره

در تلگرام `/start` بفرستید و پروژه را انتخاب کنید. برای مدیریت یک سرور «سرورهای من» و سپس نام سرور را بزنید. ساخت سرور با دکمهٔ «ساخت سرور» انجام می‌شود؛ در هر مرحله فقط به یک سؤال جواب می‌دهید. انصراف به منوی همان پروژه برمی‌گردد. پیام‌های عادی به‌جای پاسخ خام API، نتیجهٔ خوانا و دکمهٔ پیگیری نشان می‌دهند؛ وضعیت در حال انجام به معنی پایان کار نیست.

«اسنپ‌شات و بکاپ» تصاویر ذخیره‌شدهٔ پروژه را نشان می‌دهد؛ برای بازیابی، تصویر و سپس سرور مقصد را انتخاب کنید. بازیابی تمام دادهٔ دیسک سرور مقصد را پاک می‌کند و تأیید جدا دارد. «آدرس‌های IP» برای Primary IPهای پروژه است. تغییر پلن و تخصیص Primary IP نیازمند خاموش بودن سرور است؛ بات سرور را خودکار خاموش نمی‌کند.

برای تنظیمات عکس صفحهٔ سایت، وارد «سرورهای من ← نام سرور» شوید؛ بخش‌های همان سرور در همان صفحه هستند. شبکه و ISO انتخاب مرحله‌ای دارند؛ دیسک، فایروال و Load Balancer با انتخاب منبع از پروژه به همان سرور متصل می‌شوند. جزئیات و عملیات تخصصی هر منبع هم از همان بخش قابل دسترسی‌اند. فیلتر اتصال دیسک، فقط دیسک آزاد در موقعیت سرور را نشان می‌دهد.

### جداسازی و تعویض IP

«نام سرور ← شبکه و IP ← جداسازی و تعویض IP» را باز کنید. برای روش دستی، سرور را خاموش کنید و «تعویض IPv4/IPv6» یا «جداسازی IPv4/IPv6» را بزنید. برای سرور روشن، «تعویض خودکار IPv4/IPv6» را انتخاب کنید؛ IP آزاد سازگار را برگزینید و تأیید کنید تا بات سرور را نرم خاموش کند، IP را عوض کند و پس از موفقیت دوباره روشن کند. اگر مرحله‌ای شکست بخورد، journal بازیابی تلاش می‌کند IP و وضعیت اولیهٔ سرور را بازگرداند. خاموش‌کردن سرور ممکن است به‌علت کارهای در حال اجرا یا خطای داخل سیستم‌عامل موفق نشود؛ در آن صورت بات IP را تغییر نمی‌دهد. اگر IP آزاد ندارید، «ساخت IP» را از همین صفحه بزنید، پس از ساخت به سرور برگردید و IP جدید را انتخاب کنید.

IP قدیمی حذف نمی‌شود و IP جداشده ممکن است همچنان هزینه داشته باشد. اگر پیام «تغییر IP ناتمام» دیدید، وضعیت سرور و IP را بررسی کنید و دکمهٔ بازیابی را بزنید. تا تعیین تکلیف، حذف اتصال آن پروژه از بات مسدود می‌شود تا توکن مورد نیاز بازیابی از دست نرود. اگر تغییر IP در Console یا ابزار دیگری انجام شده باشد، بات برای بازنویسی آن اقدام نمی‌کند. هم‌زمان از ابزار دیگر IP همان سرور را تغییر ندهید.

### زبان بات

`/language` را بفرستید یا از فهرست پروژه‌ها و تنظیمات پروژه، «زبان / Language» را بزنید. فارسی زبان پیش‌فرض است. تغییر زبان، فرم و تأیید باز فعلی را لغو می‌کند. برای انگلیسی گزینهٔ **English** و برای فارسی **فارسی / Persian** را انتخاب کنید. فایل ترجمهٔ انگلیسی `bot/en.json` است؛ تست‌ها کامل بودن پیام‌های ثابت و حفظ جای‌نگهدارهای آن را بررسی می‌کنند.

### نمایش قیمت به یورو یا ریال

از فهرست پروژه‌ها یا تنظیمات پروژه «واحد قیمت» را بزنید؛ دستور `/currency` هم همین بخش را باز می‌کند. **یورو (EUR)** یا **ریال (IRR)** را انتخاب کنید. انتخاب برای هر کاربر مستقل است و بعد از ری‌استارت و `mhx update` باقی می‌ماند. تا قبل از اولین انتخاب، واحد اصلی حساب هتزنر مانند نسخه‌های قبلی حفظ می‌شود. تغییر واحد، فرم و تأیید باز فعلی را لغو می‌کند.

در حالت ریال، نرخ بازار آزاد ارز اصلی حساب از [NerkhAra](https://nerkhara.com/en/api/) خوانده می‌شود. خروجی تومان (`IRT`) به ریال تبدیل می‌شود: **۱ تومان = ۱۰ ریال**. نرخ دارای علامت `stale`، تاریخ متعلق به روز قبلی در منطقهٔ `Asia/Tehran`، واحد ناشناخته یا مقدار نامعتبر پذیرفته نمی‌شود. زمان به‌روزرسانی، زمان خود نرخ در منبع است و با زمان باز کردن منو جایگزین نمی‌شود. نرخ معتبر تا ۱۰ دقیقه در حافظه نگه داشته می‌شود و عبور از نیمه‌شب تهران آن را برای نمایش نرخ روز نامعتبر می‌کند. شکست دریافت نرخ، تا ۳۰ ثانیه درخواست مجدد را متوقف می‌کند.

اگر واحد حساب USD باشد و یورو انتخاب شود، تبدیل USD→EUR با نرخ مرجع [Frankfurter](https://frankfurter.dev/) انجام می‌شود؛ تاریخ واقعی نرخ مرجع نمایش داده می‌شود و ممکن است در تعطیلات مربوط به آخرین روز کاری باشد. نرخ مرجع بیش از ۷ روز پذیرفته نمی‌شود. اگر واحد حساب از ابتدا EUR باشد، نمایش یورو نیاز به دریافت نرخ تبدیل ندارد.

در صورت قطع سرویس نرخ یا نامعتبر بودن داده، **قیمت اصلی با واحد اصلی حساب** و توضیح عدم دریافت نرخ نمایش داده می‌شود؛ عدد قدیمی به‌عنوان نرخ روز یا عدد صفر به‌عنوان قیمت ریالی نمایش داده نمی‌شود. تنظیم انتخاب‌شده حفظ می‌شود تا با دریافت نرخ معتبر دوباره اعمال شود. منبع و زمان نرخ کنار انتخاب پلن، در تأیید نهایی و در صفحهٔ سرور نمایش داده می‌شود. قیمت ماهانهٔ نمایش‌داده‌شده قیمت خود پلن است؛ IP، دیسک و خدمات دیگر می‌توانند هزینهٔ جدا داشته باشند.

این قابلیت فقط نمایش تخمینی را تغییر می‌دهد؛ واحد پرداخت، صورتحساب و درخواست‌های ساخت/تغییر منابع در هتزنر تغییر نمی‌کنند. API Key هتزنر، نام پروژه و شناسهٔ کاربران برای سرویس نرخ ارسال نمی‌شوند. دریافت نرخ‌ها با کلاینت جدا و بدون کلید API اضافی انجام می‌شود.

مرجع طراحی مسیرهای ساده: [erfjab/ServerManagerBot](https://github.com/erfjab/ServerManagerBot).

## ابزارهای پیشرفته

از تنظیمات هر پروژه می‌توانید نام نمایشی و API key همان پروژه را تغییر دهید. API key جدید پیش از ذخیره با API هتزنر بررسی می‌شود؛ تغییر آن در بات، کلید قبلی را در Console هتزنر باطل نمی‌کند. این گزینه‌ها فقط برای مالک پروژه نمایش داده می‌شوند.

در پروژه، «تمام عملیات Cloud» → گروه مربوطه → عملیات را انتخاب کنید. نمونه را **با مقادیر پروژهٔ خودتان** عوض کنید؛ شناسه‌ها و نام‌های نمونه واقعی نیستند. فیلدهای اختیاری را از «راهنمای فیلدها» یا [مستندات API](https://docs.hetzner.cloud/reference/cloud) ببینید. فایل Schema راهنماست؛ خود آن را به‌عنوان ورودی اجرا ارسال نکنید.

ساخت سرور، با کلید SSH از قبل ثبت‌شده در همان پروژه:

```json
{
  "body": {
    "name": "my-server",
    "server_type": "cpx22",
    "image": "ubuntu-24.04",
    "location": "nbg1",
    "ssh_keys": [123456]
  }
}
```

نوع سرور، موقعیت و ایمیج را از عملیات فهرست همان گروه‌ها انتخاب کنید؛ دسترس‌پذیری و قیمتشان ممکن است تغییر کند. ساخت منابع هزینه دارد و قبل از اجرا تأیید می‌خواهد.

صفحهٔ دوم فهرست سرورها:

```json
{"query": {"page": 2, "per_page": 10}}
```

تغییر نام سرور با عملیات Update a Server:

```json
{"path": {"id": 123456}, "body": {"name": "new-name"}}
```

فعال کردن Rescue با عملیات مربوط در Server Actions:

```json
{"path": {"id": 123456}, "body": {"type": "linux64", "ssh_keys": [123456]}}
```

برای ادامهٔ عملیات طولانی، دکمهٔ «پیگیری عملیات» را بزنید تا وضعیت `success` یا `error` دریافت شود. در timeout بات درخواست تغییردهنده را خودکار تکرار نمی‌کند؛ قبل از اجرای مجدد، وضعیت سرور یا منبع را بررسی کنید. تکرار درخواست ساخت ممکن است منبع و هزینهٔ اضافه ایجاد کند.

## مدیریت سرویس

```bash
docker compose ps
docker compose logs --tail=50 bot
docker compose restart bot
docker compose stop bot
docker compose start bot
```

نصب، دستور `mhx` را در `/usr/local/bin/mhx` ثبت می‌کند. برای به‌روزرسانی از هر مسیر:

```bash
mhx update
```

این دستور نسخهٔ `main` را از همین مخزن می‌گیرد و بات را بازسازی و راه‌اندازی می‌کند؛ `.env` و volume پروژه‌ها حفظ می‌شوند. اگر Git خطا دهد، فایل‌های ثبت‌شده تغییر محلی داشته باشند، شاخه main نباشد یا به‌روزرسانی دیگری در حال اجرا باشد، ادامه نمی‌دهد. اگر ساخت image خطا بدهد، کانتینر قبلی پیش از ساخت متوقف نمی‌شود. دسترسی sudo ممکن است برای Docker یا ثبت دستور خواسته شود. به util-linux برای قفل `flock` نیاز است که معمولاً روی VPSهای Ubuntu/Debian موجود است. با شکست راه‌اندازی نهایی، پیام موفقیت داده نمی‌شود؛ وضعیت سرویس و لاگ را بررسی کنید.

برای نسخه‌های قدیمی که هنوز دستور `mhx` ندارند، یک بار اجرا کنید:

```bash
git pull --ff-only
bash install.sh
```

تنها یک نمونهٔ polling با یک توکن تلگرام اجرا کنید. اگر متغیرهای `.env` را تغییر دادید، برای اعمال آن `docker compose up -d --force-recreate` اجرا کنید. داده‌ها در volume پایدار `bot-data` می‌مانند؛ `docker compose down -v` آن‌ها را حذف می‌کند.

### پشتیبان‌گیری

برای کپی سازگار دیتابیس، ابتدا بات را متوقف کنید:

```bash
docker compose stop bot
mkdir -p backups
chmod 700 backups
docker compose cp bot:/app/data/projects.db backups/projects.db
cp .env backups/.env
chmod 600 backups/projects.db backups/.env
docker compose start bot
```

پوشهٔ backups را در محل امن دیگری نگه دارید؛ دیتابیس و کلید کنار هم امکان خواندن توکن‌ها را می‌دهند. برای بازیابی، `.env` اصلی را برگردانید، کانتینر را با `docker compose create` بسازید، دیتابیس را به `/app/data/projects.db` کپی کنید و مالک آن را به `10001:10001` تغییر دهید، سپس سرویس را شروع کنید. کلید جدید با دیتابیس قبلی قابل استفاده نیست.

## اجرای بدون Docker / توسعه

Python 3.13 یا 3.14:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/setup.py
python -m bot.main
```

در Windows از `.venv\Scripts\Activate.ps1` استفاده کنید. برای سرویس دائمی، روش Docker بالاتر دارای سیاست restart است؛ اجرای مستقیم در ترمینال فقط تا زمان باز بودن پردازش ادامه دارد.

تست‌ها بدون توکن واقعی و با HTTP شبیه‌سازی‌شده اجرا می‌شوند:

```bash
python -m unittest discover -s tests -v
python -m compileall -q bot scripts
bash -n install.sh
```

CI همین تست‌ها را روی Linux و Python 3.13/3.14 اجرا می‌کند و image را می‌سازد. CI شامل تست روی حساب واقعی هتزنر یا ارسال واقعی تلگرام نیست.

## امنیت و محدودیت‌ها

- `.env`، دیتابیس، لاگ، محیط مجازی و backups داخل Git قرار نمی‌گیرند. کلید واقعی را در issue، commit یا screenshot منتشر نکنید.
- توکن‌ها در دیتابیس رمزگذاری می‌شوند؛ این کار در برابر دسترسی کامل مهاجم به VPS و `.env` محافظت ایجاد نمی‌کند.
- پیام توکن و ورودی JSON به‌صورت best effort از تلگرام حذف می‌شوند؛ در صورت شکست حذف، بات اطلاع می‌دهد. پیام پاسخ محرمانه پس از درخواست شما در چت باقی می‌ماند و باید دستی حذف شود.
- تأییدها، فرم و ورودی موقت و پاسخ محرمانه فقط در حافظه‌اند و با restart از بین می‌روند. اطلاعات منقضی‌شده حداکثر در چرخهٔ پاک‌سازی ۱۵ ثانیه‌ای حذف می‌شوند.
- حذف اتصال پروژه از بات، منابع هتزنر را حذف یا توکن هتزنر را باطل نمی‌کند. برای ابطال توکن، به Console بروید. نسخه‌های پشتیبان قبلی ممکن است همچنان توکن رمزگذاری‌شده را داشته باشند.
- محدودیت نرخ هتزنر نمایش داده می‌شود؛ درخواست تغییردهنده خودکار retry نمی‌شود.
- بات بر اساس مشخصات ذخیره‌شده ساخته می‌شود؛ در زمان اجرا کد یا Schema جدید از اینترنت بارگیری نمی‌کند.

## به‌روزرسانی فهرست API

```bash
python scripts/update_catalog.py
python -m unittest discover -s tests -v
git diff -- bot/catalog.json
```

تغییر فهرست را پیش از انتشار بررسی کنید؛ شناسهٔ عملیات، روش، مسیر و ساختار ورودی مستقیماً رفتار بات را تعیین می‌کنند. مبدأ، زمان دریافت و SHA-256 نسخهٔ اصلی در `bot/catalog.json` ثبت است. این فهرست از [مشخصات رسمی هتزنر](https://docs.hetzner.cloud/cloud.spec.json) استخراج شده؛ توضیحات و Schemaهای هتزنر متعلق به منبع اصلی‌اند. کد این پروژه با مجوز MIT منتشر می‌شود.
